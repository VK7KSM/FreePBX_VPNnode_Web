# 有界定位模拟

用于项目所有者明确授权的D22定位、位移报告与回退验收。它是短期诊断载荷，通过现有文件传输和远程终端运行，不编入生产客户端，不设置永久模拟开关。

## 执行与恢复

1. 先保存原构建、定位源、模拟定位AppOps、电量与网络状态，以及服务端最新位置和客户端移动基点的私有原始证据。检查没有其他模拟定位工具正在运行；不得覆盖已有测试定位源。
2. 使用`build-location-simulation.ps1`构建到新的捕获目录，保存源码、制品和哈希；通过elfRemote发送文件，核验设备哈希及R2暂存清理。
3. 先运行`LocationSimulationProbe read`验证包名与UID匹配及定位接口可访问。运行入口为`CLASSPATH=<制品路径> app_process /system/bin net.elfradio.elfremote.diagnostics.LocationSimulationProbe`，由已授权root通道启动，实际定位调用降至shell身份。
4. 启动独立的本地恢复助手并确认就绪，再临时设置`appops set com.android.shell android:mock_location allow`。恢复助手须停止模拟、撤销测试源并恢复保存的原定位源设置和AppOps，不得用固定值覆盖未知基线。
5. `run <控制文件路径> --bounded`替换GPS与网络测试源。控制文件使用原子替换更新，目录和文件仅需shell可读；`{"mode":"fix","lat":0,"lng":0}`每秒送入一个新鲜坐标，`{"mode":"empty"}`不送定位，`{"mode":"stop"}`结束。示例零坐标只是格式说明，实际模拟点须预登记，不当作真实位置。
6. 模拟进程最多运行15分钟，正常退出和异常路径均撤销本进程添加的测试定位源。独立`cleanup`入口用于恢复助手再次幂等清理；恢复失败必须保留错误，不能继续新的模拟。主机断开仍由本地助手恢复原配置。
7. 从已有坐标切换到无GPS条件时，必须先结束会话并清理，再启动新的`empty`会话；直接改为`empty`不会消除先前注入的有效缓存。系统总定位开关和无线采样权限保持开启。
8. 结束后核验没有测试定位源、原GPS及AppOps已恢复，再取得真实GPS报告恢复移动基点。历史模拟记录保留私有时间段与报告编号，不能当自然移动验收证据。

## 判定

- 位移验收必须使用实际蜂窝网络。先建立已确认基点，注入不足3公里位置确认不报告，再注入超过3公里且扣除两次精度半径仍超过阈值的位置确认`movement`报告，原地再次检查不得重复。可加速调用既有`WAKE`的`movement`入口；不得用强制报告替代位移判定。
- Google回退要求实际报告无GPS定位，实际无线采样经生产服务端得到Google结果；仅直接调用Google接口成功不代表完整链路通过。
- 所有结果注明模拟条件，真实外出移动、真实低电量与深睡是不同验收，不能相互替代。
