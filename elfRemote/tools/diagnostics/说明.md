# 独立云连接的闹钟验证工具

`CloudWakeProbe.java`用于验证独立`app_process`能否以elfRemote应用UID接收系统闹钟。它不安装APK、不建立网络连接、不切换现有MQTT连接，也不修改系统设置。

使用`build-cloud-wake-probe.ps1`，显式指定新的输出目录、JDK目录和Android SDK目录，生成`probe.zip`。脚本拒绝覆盖已有输出目录。使用现有“发送文件”功能传到测试机，核验SHA-256后，以已核实的elfRemote应用UID运行：

```sh
CLASSPATH=<设备上的验证制品路径> app_process /system/bin net.elfradio.elfremote.diagnostics.CloudWakeProbe
```

输出`application_uid_matches`、`alarm_fired`、请求间隔、实际间隔及延迟。工具注册一次5秒系统唤醒闹钟，最多等待20秒，结束时取消监听并退出。必须检查真实输出及退出码，不能把成功启动进程当成闹钟通过。

第三版增加`ALARM_REGISTERED`事件和注册、到期时刻。主应用中断尝试必须等该事件出现后才能停止应用，不能用固定等待一秒猜测注册已完成。

附加参数`--system-owner`时必须由root运行，改用系统Context注册闹钟，并输出`system_owner=true`。此模式只验证独立核心的唤醒职责，不建立root网络连接；后续云联网仍需保持elfRemote应用UID的流量归属。

2026-09-09，XX应用UID基础尝试的5秒闹钟实际间隔5009毫秒；该模式的主应用停止尝试未收到闹钟。第三版系统所有者尝试在明确注册后停止主应用，仍于5007毫秒收到闹钟，停止后及闹钟结束时主应用均不存在，随后守护自动恢复。失败记录与旧助手注册顺序不确定的限制保留在开发进度文档。

USB充电时普通闹钟到达不代表深度休眠已通过；当前主应用仍持有生产MQTT连接。此工具是迁移前的接口验证，不是已交付的独立云连接。

测试目标、制品哈希、原始命令与回执保存在私有捕获目录，不能将真实设备标识或凭据提交仓库。
