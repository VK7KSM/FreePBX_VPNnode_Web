# D31 独立发布通道与自行发布说明

## 适用范围

D31 开发任务今后可以直接发布 APK 和下发更新，不需要修改 Web 源码、不需要重新部署 Worker，也不需要等待另一个任务配合。继续使用现有管理员登录会话和发布清单签名，不新增登录体系。

- D31 通道为 `d31`，包名为 `net.elfradio.d31bootstrap`，清单型号为 `mdl_d31`，沿用原 D31 APK 证书。
- D22 通道为 `d22`，原索引、旧清单和下载链接继续兼容。两种机型的相同版本码互不覆盖。
- 网页根据实际设备身份及型号选择通道，只列出适用版本，最新版本在最上方。同一通道同版本码不能换成不同 APK；代码变化必须增加版本码。
- 发布与安装分开。工具默认只上传并核验；只有显式指定 `--assign` 才下发任务。
- D31 必须实际启用独立更新器，并上报 `managed_update: true` 和 `managed_update_v2: true`，才能下发。服务器不能代替设备声明更新器已可用。

## 另一开发任务的操作顺序

从完整工作区执行现有 D31 清单准备工具。`D31_UPDATE_SIGNING_KEY` 指向本机已有的发布清单私钥文件；不能改用 APK 签名密钥，不能把私钥或会话内容写入文档、命令输出和 GitHub。

```powershell
node research/d31_adb_bootstrap/tools/prepare-remote-release.mjs <APK路径> <实际APK元数据JSON路径> <目标设备编号> <新的私有发布JSON路径>
```

准备工具会核对实际 APK 元数据、大小、摘要及 D31 证书，生成独立发布编号、原文签名清单和制品。当前工具生成的清单有效期为一小时，必须及时发布、下发；过期后针对同一制品生成新发布编号及有效清单即可，无需提高未改变制品的版本码。旧任务的下载映射不会被新清单覆盖。

再进入 Web 仓库，使用新的通用发布工具：

```powershell
node elfRemote/tools/publish_release.mjs --input <私有发布JSON路径> --session <管理员会话JSON路径>
```

会话文件使用浏览器自动化的存储状态格式，含生产站点的 `elf_admin` Cookie；本工作区已有 `.wrangler/progress-session.json`，失效时通过正常网页登录刷新会话。工具只向 `https://v.elfradio.net` 发送会话，拒绝重定向；本机公钥验证清单，再二进制上传，检查版本目录并下载核对长度及摘要。输出仅含通道、版本、大小、摘要和结果。

需要立即更新明确目标时，在同一命令末尾增加：

```powershell
--assign <目标设备编号>
```

工具先完成发布与下载核验，再调用分配接口，触发现有 MQTT 通知。返回 `assigned: true` 仅表示更新已下发，必须继续查看实际设备版本与安装结果，不能当成安装成功。若下发失败而上传已成功，制品仍保留，可修复设备能力后从网页下发，无需重复上传。

当前 D31 清单准备工具绑定一个目标设备。服务端协议也支持不含 `device_id` 的同机型通用清单；如未来有多台 D31，可由 D31 发布工具生成这种清单，服务端与网页不需要再改。不要用另一台设备专用清单冒充通用版本。

## 接口合同

| 操作 | 接口与字段 |
| --- | --- |
| 读取 D31 版本 | `GET /api/elfremote/releases?channel=d31` |
| 读取设备适用版本 | `GET /api/elfremote/releases?device_id=<设备编号>`；返回 `channel` 和降序版本列表 |
| 二进制上传 | `PUT /api/elfremote/releases/upload`；正文为 APK，提供 `Content-Length`、`X-Elf-Manifest`（UTF-8 原文的 Base64）、`X-Elf-Signature`（十六进制签名）、`X-Elf-Publish-Only: 1` |
| 兼容 JSON 上传 | `POST /api/elfremote/releases`；`manifest_raw`、`signature`、`apk_b64`、`publish_only: true` |
| 下发 | `POST /api/elfremote/assign`；`device_id`、`channel: "d31"`、`versionCode`、每次操作独立且重试复用的 `request_id` |
| 下载 | `GET /api/elfremote/apk/<清单job_id>`；保持原下载合同，不需要管理员 Cookie |
| 领取 | 原上报/拉取接口返回 `managed_update`，保留 `manifest_raw`、`signature`；另附 `task_id`、`task_device_id`、`task_expires_at` |
| 安装进展 | `POST /api/elfremote/update-progress`；设备凭据、`job_id`（本次 `task_id`）、`state`、`detail`；实际新核心健康后回报 `success` / `health-ok` |

清单必须保留 `package`、`channel`、`model_id`、`versionCode`、`versionName`、`certSha256`、`size`、`sha256`、`job_id`、`expires_at`、`url`。`expires_at` 与任务期限均使用毫秒。任务编号和发布编号不同，禁止互换。JSON 原文字节参与签名，不能重新序列化后继续使用旧签名。

D31 独立版本键为 `elfremote_rel_d31_<版本码>`，目录为 `elfremote_releases_d31`。D22 继续使用原 `elfremote_rel_<版本码>` 和 `elfremote_releases`。新下载映射固化制品对象键，兼容原 D22 数字映射；跨通道、错包、错证书、过期、错目标及同版本替换制品均明确拒绝。
