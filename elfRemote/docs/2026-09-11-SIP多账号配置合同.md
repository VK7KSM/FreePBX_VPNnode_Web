# SIP多账号配置接口约定

日期：2026-09-11。交付方：D22_Web_Dev；设备端对接方：D31_dev。

## 范围与分工

本次扩展现有系统配置→账号配置及`configure_sip`任务，不新增服务器、不接管SIP保活、不改变Nexui电话或QUIK短信启动顺序。Web支持按应用及稳定账号标识分别保存、配置、恢复和显示状态；D31端负责真实账号应用、结果读取和真机验证。

Nexui只声明已经实现配置能力的线路；QUIK现阶段只声明`default`单账号，不能把Web可表达多账号当作QUIK已经支持多账号。Web不负责创建或删除设备账号槽位，不发送真实电话或短信验收请求。

## 能力及账号列表

在`POST /api/devices/report`每次完整报告中同时携带以下字段。示例为合成账号，不是真实设备数据；其他既有报告字段省略。

```json
{
  "managed_sip_account": true,
  "sip_targets": [
    {
      "target": "nexui",
      "label": "Nexui 电话",
      "auth_username_supported": true,
      "accounts": [
        {"account_id": "line-a", "label": "线路一"},
        {"account_id": "line-b", "label": "线路二"}
      ]
    },
    {
      "target": "quik",
      "label": "QUIK 短信",
      "auth_username_supported": false,
      "accounts": [{"account_id": "default", "label": "短信账号"}]
    }
  ]
}
```

- `target`当前接受`linphone`、`nexui`、`quik`。每种目标只能出现一次，每种最多32个账号；未实现的目标不要声明。
- `account_id`为1至64位字母、数字、下划线或连字符。D31端负责稳定映射；Nexui数据库`_id`可能复用，不得未经确认直接作为永久账号标识。Web只当不透明字符串，不解析其语义。
- `auth_username_supported`只有严格布尔值`true`才表示支持独立认证用户名。QUIK当前设为`false`，Web隐藏该输入，并拒绝与登录账号不同的认证用户名，不能静默忽略。
- 新合同必须在每份报告中重复声明实际目标。`sip_targets: []`表示当前没有可配置槽位；缺少整个字段表示旧单Linphone合同。撤销或缺少新合同声明时，不再向本次报告领取端交付旧多账号任务。未声明的配置仍保存在私有记录中，不自动恢复或显示为可操作。
- 不按D22或D31型号写死账号能力。D31当前尚未声明时，不会凭机型自动打开表单。

## 下发任务与去重

管理会话调用既有`POST /api/elfremote/task`：

```json
{
  "device_id": "synthetic-device",
  "id": "sip-synthetic-task",
  "type": "configure_sip",
  "params": {
    "target": "nexui",
    "account_id": "line-a",
    "server": "sip.example.invalid",
    "username": "example-account",
    "auth_username": "example-auth",
    "password": "synthetic-password",
    "transport": "tls",
    "port": 5061,
    "realm": "example.invalid"
  }
}
```

- `target`与`account_id`必须同时存在，并精确命中设备声明；缺一、未知目标、未知槽位或不支持的独立认证用户名拒绝。
- `auth_username`缺省使用`username`。`realm`可省略，允许1至253位字母、数字及`*_.@:-`；不支持控制字符或配置注入。空白表单不下发`realm`。
- `transport`接受`tls/tcp/udp`；TLS缺省端口5061，其他5060。服务器和账号沿用原参数校验。
- 任务编号和原有幂等键继续生效；目标、账号、认证域和其他规范化参数都参与请求摘要。同编号同参数返回`duplicate:true`；同编号改目标、账号或参数返回现有幂等冲突错误，HTTP 400，不覆盖原任务。未支持目标的能力错误为HTTP 409。
- 通过报告响应中的`managed_task`领取，保留`managed_exec_v1:true`。目标设备使用自己的既有凭据领取密码；管理员公共设备列表、公共任务和历史不返回密码。
- 仍使用单设备已有任务占用，多个账号逐个配置，不添加并行执行或新排队体系。

## 配置回执

继续调用`POST /api/elfremote/task-progress`，带既有设备凭据、`task_id`及状态。`claimed`表示接收、`running`表示正在配置。新合同的最终成功结果必须包含：

```json
{
  "target": "nexui",
  "account_id": "line-a",
  "applied": true,
  "action": "completed",
  "exit_code": 0,
  "text": "配置已写入"
}
```

- `success`只表示真实配置已写入并核验，不要求同时注册成功。界面显示“配置已写入”，不能伪装成“已注册”。
- `success/failed/rejected`均须在`result`中带原任务对应的`target/account_id`；不匹配返回400。成功还必须有以上写入证据。
- 失败填简明`reason`或`text`；可附脱敏`detail`。客户端任何日志或回执均不得输出密码。服务器额外过滤任务和已保存配置的已知密码及URL编码，舍弃SIP结果中的任意制品对象；这不能替代客户端不记录秘密。
- 失败不覆盖上次成功保存的配置。相同最终结果重传不重新写入结果或改变完成时间。每账号最近配置结果独立保存，换到另一任务后仍可查看。

## 注册状态独立上报

完整报告增加`sip_registrations`数组，每项为一个实际采样的账号状态，最多96项：

```json
{
  "target": "nexui",
  "account_id": "line-a",
  "state": "registered",
  "reason": "",
  "sampled_at": 1789090000000,
  "config_task_id": "sip-synthetic-task"
}
```

- `state`接受`registered/registering/unregistered/failed/unknown`，分别显示已注册、正在注册、未注册、注册失败、状态未知。`sampled_at`是实际采样时刻的毫秒整数，不是旧状态上传时新造的时间；未来超过服务器60秒拒绝。
- `config_task_id`是当前实际生效配置的任务编号。Web保存过该账号配置后，必须匹配最近成功配置任务；旧配置结果不会覆盖新配置。设备上原来就有但未由Web保存的配置，可省略该字段。
- 相同安装及配置下，较旧或相同采样时间不覆盖已有采样；新安装或新配置单独处理。不把未知、离线、历史成功当作当前注册。
- Wi-Fi/有线样本有效窗口为15分钟加90秒，其他网络为60分钟加90秒；设备离线、样本过期、新配置进行中、配置编号不匹配或安装凭据已改变时显示待确认。窗口沿用设备报告合同，不增加设备轮询或新SIP保活。
- 正常上报漏掉注册数组不会删除历史采样，但历史会到期。读取失败请真实报告`unknown`及原因，不延长旧成功样本的时间。
- Web状态刷新包含注册样本到期点，无须密集拉设备；公开`sip_accounts`按目标和槽位输出`configuration`摘要、`configuration_result`及`registration`，不暴露安装凭据、私有哈希或密码。

## 保存、恢复与旧D22兼容

多账号私有配置使用`account_configs["sip:" + target + ":" + account_id]`，互不覆盖。旧D22继续使用`account_configs.linphone`，未携带新目标字段的旧Linphone任务仍要求原`registered:true`成功证据；Zello保持原行为。

安装身份更新后，只恢复仍声明且仍支持的账号槽位；每账号复用原最多3次有界退避，明确凭据错误或设备拒绝停止重试。成功写入后不因注册失败反复覆盖账号；正常注册恢复仍归原SIP应用负责。Web合同测试覆盖恢复逻辑，不等同D31真实刷后恢复已验收。

## 验证与后续检查

新增11项多账号测试，与旧4项SIP测试及全套回归共同通过，共263项。覆盖真实Worker路由的报告、领取、保存、隔离、幂等、拒绝、失败、密码过滤、注册新鲜度、新安装恢复、槽位撤销、表单切换和编辑期间账号列表变化；没有向真实D31下发账号配置。

Playwright使用本机合成账号页面核验桌面排版、切换后服务器和账号正确预填、密码不串用、QUIK隐藏独立认证字段及390像素页面无整体横向溢出。截图仅为布局示例，不能作D31已登录证据。

D31_dev接到交付后请按此合同继续实现、检查真实接口；有Web缺陷发回具体字段、最小复现及脱敏结果，没有缺陷则继续原开发计划。其他系统设置、日志/自愈/重启及Windows刷机阶段仅在真实客户端验证发现既有接口不足后提交增量，不因此提前建设刷分区界面。

### 2026-09-11 D22_Web_Dev：账号页面按型号预设的更正

用户明确要求页面的软件分类由Web按设备型号预设，不等待客户端能力报告。D31现在直接显示Nexui电话和QUIK短信表单，D22显示Linphone与Zello；H13依据已有软件记录预设Zello，其余尚无已确认预装清单的型号不套用D22页面，已声明的账号软件可自动加入。型号改名按不变的registration_key识别。

此条更正前文未声明时仅显示空状态的页面说明，不改变任务合同：客户端尚未声明实际槽位时，预设表单不可提交，不生成虚假account_id；能力到达后自动显示真实线路和结果。每设备保存所选软件，SIP线路按当前软件筛选，Nexui与QUIK不在同一表单混列。任务接口、配置写入与注册状态合同保持。
