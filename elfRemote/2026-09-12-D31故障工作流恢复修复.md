# D31 故障工作流恢复修复

日期：2026-09-12。执行者：D22_Web_Dev 的故障模块协作任务。本次仅修改浏览器故障模块、生成文件和独立测试；未操作 D31、未调用生产接口、未创建媒体会话、未提交或部署。共享开发记录由主任务统一追加。

## 已修复问题

1. **新目录初始化覆盖持久任务。** 目录选择器仍在用户点击时打开，取得目录后再进入互斥范围。目录初始化与所有故障操作共用 `elfremote-fault-workflow` 锁，持锁后重读磁盘，只有真正不存在时才新建状态。另一页面占锁时本次立即停止并提示重试，不使用锁外读到的旧状态。采用同源统一锁也覆盖不同设备误选同一目录；持久状态的目标及版本不符时拒绝，不覆写。
2. **服务器暂存失败阻断已有本机包恢复。** `DOWNLOAD` 先读取已登记本机包并检查长度、SHA-256。符合回执时直接进入本机完整 ZIP、清单、逐项原件校验；不再请求服务器暂存元数据或下载，不创建新的导出和取回任务。整包摘要符合但内部原件清单错误仍拒绝归档。
3. **异常本机包被同名覆盖。** 长度或摘要异常的原件保留，文件名及原因进入持久状态并在页面显示。每次需要网络下载都分配新的、不存在的文件名，先保存名称再请求服务器；旧包不覆盖。网络、写入失败保留原任务及新尝试名称。权限拒绝、文件超过读取上限等错误直接停止，不当作文件缺失。最多登记 64 份异常包，达到上限后停止追加，已有原件与记录不删除。

## 容量含义

- `IN_FLIGHT_AND_RETAINED_BUDGETS` 策略分别显示在途采集 `collectingEvents / maxCollectingEvents`、采完待归档 `awaitingArchiveEvents`、未归档合计 `activeEvents`、全部保留 `retainedEvents / maxRetainedEvents` 及原件总字节预算。未归档合计不再冒充 32 条在途采集门。
- 旧 `UNARCHIVED_EVENT_LIMIT` 保留按未归档事件数限制的显示。缺失字段、负值显示未知，不推断为零。
- 显示 `continuationAction` 对应处理建议、容量限制具体原因，以及 `uncollectedSourcesMayExpire` 的是／否／未知。
- 归档完成说明改为事件不再计入未归档数量；设备原件和保留空间仍保留。归档不能释放保留原件字节，也不能保证解除所有容量限制。
- 容量标明最近扫描时间、不是实时容量。核查时 `FaultMonitor` 已保存 `uncollectedSourcesMayExpire`，但 `FaultPending` 尚未透传，因此当前页面对此显示未知；已向主任务交接客户端字段缺口。

## 保留边界与待验

- 锁覆盖同一来源、同一浏览器配置下使用本版模块的页面。旧版已打开页面应刷新；不同浏览器、配置目录、电脑或命令行宿主不共享此锁。同源不同设备的故障保全也会短暂互斥，避免共用目录时出现交叉写入。
- 刷新后仍须重新选择原目录与原事件，不自动恢复文件系统权限，不导入命令行宿主队列。
- 仍绑定原设备及报告版本；不改旧状态强行跨版本恢复。服务暂不可用保留原任务，不改有效期或换号补交。
- 下载中途刷新仍从头下载同一取回任务，不具备字节级断点续传。异常字节已保存的文件保留；尚在网络内存中的字节不宣称已经落盘。
- 正确本机包恢复仍包含现有设备列表校验，不宣称完全离线；确认归档之前仍重新读取本机包并逐项校验。
- 原生 Chrome／Edge 的选择目录、授权取消或撤销、真实文件关闭、刷新恢复及归档完整流程仍需后续有界实测。当前离线通过不能替代这些验收，也不代表生产已上线。

## 同日上线后独立复审与补修

主任务报告首批 `d7f993a` 已部署后，再次只读检查最终源码及 D31 最新需求，发现并获主任务指派修复以下问题：

1. 操作按钮点击后，设备列表核查存在异步等待；事件行此前仍可切换，后续可能读取新选事件。现已在点击时冻结事件编号，处理中禁止行切换；详情、取回和归档均使用冻结编号。离线延迟设备查询、快速切换事件的行为测试证明命令仍绑定原事件。
2. 已有状态文件如果是合法 JSON `null`、`false` 或 `0`，旧代码会按不存在初始化并覆盖。现仅确切 `NotFoundError` 允许创建；空值、错误结构及损坏状态保留原字节并拒绝。六种错误结构均验证不会写文件或发请求。
3. 状态写入此前不限制体积，读取却限制 1048576 字节。多事件累积可能写出下一次无法加载的状态。现写入前按实际 UTF-8 字节执行同一上限，超过时停止，保留最后可读状态；不截断或删除历史、不创建尚未持久化的新任务。接近上限的状态写入失败及重新加载测试通过。达到上限后的记录整理仍需人工核查，本轮不更改状态格式，也不宣称无限容量。
4. 故障请求此前把 `Retry-After` 截短至五分钟，二进制下载没有统一处理退避。现元数据与二进制下载共同接受长秒数及 HTTP 日期，到服务器要求时刻前禁止继续请求；缺失、错误或已过期值使用十五秒最小退避。模拟到 UTC 午夜的十二小时退避，六分钟后没有提前请求，期限到达后复用原取回任务完成。该退避仍只保存在当前页面内存，刷新不会恢复它。
