# Pixel 网关 SIP 远程配置合同

日期：2026-09-16。Web/Workers 交付方：D22_Web_Dev；Pixel 客户端对接方：SIP_Dev。

## 复用范围

Pixel 网关继续使用现有`configure_sip`任务、单设备任务占用、幂等键、过期时间、`task-progress`和MQTT `push-sync`。不新建任务队列，不把Pixel当作Linphone，也不改变D22旧Linphone、D31 Nexui/QUIK的合同。

## 能力声明

客户端完整报告必须包含`managed_sip_account=true`，并声明唯一目标：

```json
{
  "sip_targets": [{
    "target": "gateway",
    "label": "Pixel 网关",
    "auth_username_supported": false,
    "accounts": [{"account_id": "primary", "label": "主网关账号"}]
  }]
}
```

Gateway只接受单一`primary`账号，不接受独立认证账号。可通过`realm_supported=false`明确关闭认证域；省略时Web允许可选`realm`。只有设备本次报告仍声明同一`gateway/primary`能力时，`push-sync`才会即时返回该任务。

## 配置任务

管理员继续调用`POST /api/elfremote/task`，任务字段包含`id`、`idempotency_key`、`expires_at`、`type=configure_sip`。参数公共字段为`target=gateway`、`account_id=primary`、`server`、`username`、`transport`、`port`和可选`realm`。

密码必须严格二选一：提交非空`password`表示设置新密码；提交`keep_password=true`表示保留设备现有密码。两者同时存在、两者都缺少、空密码、`keep_password=false`或Gateway携带`auth_username`都会被拒绝。Gateway只接受`tls/udp`和1至65535端口，不显示或接受`tcp`；D22/D31既有目标仍接受`tls/tcp/udp`。服务器、账号和认证域沿用现有严格校验。

页面默认勾选“保留现有密码”，此时密码输入框禁用且请求中完全不包含`password`。取消勾选后必须填写新密码。公开设备列表、任务、历史、状态、错误和页面均不返回密码；新密码只在私有任务中短暂交付设备并按既有规则保存，终态任务参数立即清空。

## 回执与状态

客户端按既有状态推进`pending/claimed/running/success/failed/rejected/expired`。`success/failed/rejected`结果必须匹配`target=gateway`和`account_id=primary`；成功还必须包含`applied=true`、`action=completed`、`exit_code=0`。

首次联调使用当前页面公开字段并保持“保留现有密码”勾选。客户端在字段完全相同时执行无修改、无重启的no-op，只核验当前SIP注册并返回成功证据。注册状态继续通过`sip_registrations`上报，页面分别显示公开配置、最近配置结果和注册状态，不把配置成功冒充注册成功。

## 安全与兼容边界

服务端从不从设备获取密码。若服务器此前已私密保存过管理员输入的密码，后续`keep_password=true`成功不会清除该既有私密值；若从未保存过密码，只保存保留密码语义及公开配置。D22旧单Linphone和D31多账号参数、密码要求、恢复与结果规则保持不变。
