# SIP封禁管理交接

日期：2026-09-13。开发：SIP_Dev。部署：按用户最新要求交给D22_Web_Dev，本任务不自行部署。

## 功能

- 分机编辑窗口增加封禁或解封按钮，显示最近关联的出口地址及同出口分机。操作立即执行，不依赖保存分机配置。
- 服务器实际封禁且状态新鲜时，分机列表的传输列显示红色“封禁”。离线不等于封禁；接口异常时禁用操作。
- 后端仅允许现存分机、指定动作及服务器已知且匹配的地址。执行参数数组形式的Fail2Ban命令，不拼接命令行，不接受任意命令。
- 解封只移除目标地址的Asterisk封禁，保留其他攻击来源及防护配置。密码错误持续重试仍可能再次封禁。
- 这是出口地址管理，不是永久停用账号。同出口设备一起受影响。失败注册中的分机号未经认证，关联属于排障线索；界面明确展示操作地址，不能把关联当作设备身份验证。

## 改动位置

- `sip-client.js`及生成的`sip-client-source.js`：显示与按钮。
- `worker.js`：受现有管理员会话和来源验证保护的`POST /api/sip/ban`，转发至既有大阪隧道。
- `sip-server/files/usr/local/sbin/sip_bans.py`：读取封禁、增量读取失败注册日志、保留最近联系人地址、执行并核对操作。
- `sip-server/files/usr/local/sbin/sip-statusd.py`：每轮采样更新状态，提供令牌保护的操作接口。
- 状态库新增`ban_endpoints`和`ban_status`，不修改账号密码和拨号计划。

## 用户临时解封请求

本轮两次只解除已核实的共享出口封禁。第一次解封后其中一个账号恢复TLS注册，另一个继续认证失败并再次触发封禁；用户再次要求后已第二次解封。不得把解封完成写成错误凭据已修复。
